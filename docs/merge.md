# マージ（`kek merge` と git のマージドライバ）

## 目的

main から切った worktree で複数のエージェントが並行して実装すると、マージのたびに同じ形の衝突が起きる。このリポジトリの過去のマージ（`git show --remerge-diff` で再現できる）では、衝突のほとんどが「両方のブランチが同じ場所に別々の行を足しただけ」だった。

- README のコマンド表に両方が 1 行ずつ足す
- `kek` の usage と `case` に両方がコマンドを足す
- `tests/run.sh` のスイート一覧（同じ 1 行の `all="..."` に両方が単語を足す）
- `compiler/main.kek` の `if cmd == "..." { return ...; }` の並びに両方が足す
- `compiler/prelude_src.kek`（`lib/prelude` を文字列として埋め込んだ生成物）

git は「同じ場所への追加」を衝突にする。しかも両側の追加の末尾が同じ行（`}`）だと、それを衝突の外に出すので、単純に両方を残すと括弧の対応が壊れる。`kek merge` はこれらを機械的に解決し、人間（とエージェント）は本当に意味のぶつかる衝突だけを見ればよいようにする。

## 使い方

```sh
mise run hooks   # scripts/install-hooks.sh：pre-commit フックとマージドライバ kek を登録
```

これで `.gitattributes` が `merge=kek` を指定しているファイル（`*.kek`・`*.md`・`*.sh`・`kek`・`*.toml`・`*.lean`・`*.js`・`*.mjs`・`*.yml`）のマージに `scripts/merge-driver.sh` が使われる。設定は `.git/config` に入るので、clone の全 worktree で共有される。登録しなければ git は普段どおりにマージする。

ドライバはまず git 自身の 3-way マージ（`git merge-file`）を試し、それが衝突したファイルだけを `kek merge` でマージし直す（git が衝突なく済ませたものはそのまま）。`kek` を動かせないとき（その checkout のコンパイラがビルドできない、`kek merge` より古い、など）は git の結果（衝突マーカー付き）を残す。`$KEK` で使う `kek` を変えられる。

直接使うこともできる。`git merge-file` と同じく結果を `<ours>` に書き、衝突がなければ終了コード 0、あれば 1。

```sh
./kek merge [-p] [-no-ast] [-path p] [-marker-size n] \
    [-ours-label l] [-base-label l] [-theirs-label l] <ours> <base> <theirs>
```

- `-p`：`<ours>` に書かずに標準出力へ
- `-path`：ファイルの種類を決めるパス（git の一時ファイルを渡すとき。既定は `<ours>`）。`.kek` なら構文木でマージする
- `-no-ast`：`.kek` もテキストとしてマージする

## テキストのマージ

各側の変更を base に対する hunk（Myers の差分）にし、2 つの側の hunk が base の上で重なるか、同じ位置に挿入するときだけ「衝突の候補」としてまとめる。隣り合うだけの変更（ours が 2 行目、theirs が 3 行目を変更）は git と違って両方取り込む。候補は次の順に解決する。

1. 両側が同じ、または片側が base のまま → もう一方
2. 両側とも挿入だけ → 両方残す（ours が先）。片方がもう片方を前後に延ばしたものなら長い方。git と違い、両側の挿入に共通する末尾（`}`）を切り離さないので、`if` ブロックを 2 つ足しても括弧が崩れない
3. 同じ行数を書き換えた → 行ごとに単語単位（英数字・`_`・`-`・非 ASCII の並び、空白の並び、それ以外の 1 文字）で同じ規則を当てる。`all="a b"` に両方が単語を足す、`usage: (a|b)` に両方が `|c` を足す、が解決する
4. それ以外 → 衝突（diff3 形式のマーカー。base の内容も入る）

両側がファイルを新しく作った（base が空の）ときは、行を両方残すことはせず、共通の行を 1 回だけ出して違う行を衝突にする（git の add/add と同じ）。

両方を残すと同じものが二重になる場合は衝突にする。片側が残す挿入が、もう片側が（base になく）新しく足したコードを含むとき、つまり両側が同じ定義を別々に足したときだ。比べるのは「続く 2 行がどちらも 6 文字以上」の組と、見出し行（シェルの `name() {`、Markdown の `# ...`）。例えば両側が別の場所に別の中身の `ncpu() {` を足すと衝突になる（このリポジトリの d50d09e で実際に起きた）。

## Kekkai のソースのマージ

`.kek` で、3 つの版がすべて構文解析できるときは、構文木の単位でマージする。

| 単位 | 対応づけ |
| --- | --- |
| トップレベルの item（`fn`・`struct`・`enum`・`trait`・`impl`・`type`） | 名前（`impl` は `impl Trait for Type` の見出し） |
| `impl`・`trait` のメンバー、struct のフィールド、enum のバリアント | 名前 |
| 関数の本体・`while`／`for`／`if`（`else` なし）のブロックの文 | 内容（トークン列。整形とコメントは無視） |
| `match` の腕 | パターン |

単位はそれぞれ、直前の単位の終わりから自分の最後のトークンまでの行（上に付いたコメントを含む）で、空行の数は別に持つ。単位が 1 行に 1 つずつ並んでいない（`fn f() { a; b }` のような）コンテナや、切り分けて元の文字列に戻らないものは、テキストとしてマージする。

- 名前で対応づける単位は、並び順を行と同じ規則でマージし（両側の新しい名前を残す）、中身は名前ごとにマージする。片側が移動し、もう片側が中身を変えた関数もマージできる。片側が消して、もう片側が変えたものは衝突（消した側は空）。両側が同じ名前を違う中身で足したら、共通の行は 1 回だけ出し、違う行を衝突にする（git の add/add と同じ。両方は残さない）
- 内容で対応づける単位（文）は、行と同じ規則で並びをマージする。両側が変えた範囲は、単位の数が同じなら 1 つずつ（入れ子の構文木で）マージし、違えば文字列リテラルの中身を除いた形（骨格）で並べ直してもう一度試し、だめならテキストとしてマージする
- 単位のテキストが衝突しても、違いが文字列リテラルの中だけなら、リテラルの外を行でマージし、各リテラルの中身（エスケープを戻した文字列）を行でマージして書き戻す。`compiler/prelude_src.kek` で両側が同じ埋め込みファイルの別の場所を変えた場合がこれで解決する（いずれにせよ `./kek` が `lib/prelude` から作り直す）
- 衝突がなく、結果が構文解析できなければ、ファイル全体をテキストとしてマージし直す

## 限界

- 意味の衝突（両側の変更はそれぞれ正しいが、組み合わせると型が合わない、など）は見つけない。マージ後に `mise run test` や `kek check` で確かめる
- 両側が同じ場所に足したものの順序は ours が先で、意味では選ばない
- `kekkai.assure.lock`（JSON）・テストの golden ファイル・`bootstrap/kek.wasm` にはドライバを使わない（JSON の行を並べるとカンマが壊れる。golden は作り直すもの）

## 実装

`compiler/merge_main.kek`（`mg_`）。テストは `tests/run.sh merge`（`testdata/merge/<case>/` の 3 版と `tests/merge/golden`、一時リポジトリでのドライバ）。
