# モジュール

1 ディレクトリ＝1 プログラムのまま、サブディレクトリをモジュールにする。Go のパッケージの発見のしかたと Rust のパス・`pub`・`use` を組み合わせた、保守的な設計にしている（書き方の要約は [language.md](language.md) の「プログラムの構成」）。

## 決定事項

| 項目 | 決定 |
| --- | --- |
| モジュールの単位 | プログラムのディレクトリのサブディレクトリ `foo/` がモジュール `foo`。入れ子のディレクトリ `a/b/` は `a::b`。中の `*.kek` すべてが 1 つのモジュールを作る |
| ルートモジュール | プログラムのディレクトリ直下のファイル（従来どおり）。1 ファイルのプログラムはルートモジュールだけ |
| 宣言 | `mod foo;` は書かない（Go と同じくディレクトリから発見する）。ファイル内の `mod foo { ... }` は入れない（予定なし。ファイルを分ける） |
| 可視性 | 項目（`fn`・`struct`・`enum`・`trait`・`const`・`type`）は `pub` を付けない限り、定義したモジュールとその子孫からだけ見える（Rust と同じ）。モジュール自体は常に公開 |
| ルートの項目 | 従来どおり `pub` は要らない（ルートの子孫＝プログラム全体から見える）。ただしサブモジュールからは `crate::x`・`super::x`・`use` で名指す（暗黙には見えない） |
| メソッド・フィールド | 固有の `impl` のメソッド・関連関数と struct のフィールドも `pub` がなければ非公開。メソッド呼び出し・`Type::f`・フィールドの読み書き・struct リテラル・struct パターンで検査する。enum の variant、trait のメソッド、trait の実装のメソッドは型・trait と同じく公開。`impl` の関連定数は常に公開（未対応） |
| パス | `foo::bar()`・`foo::Type`・`foo::Type::method()`・`foo::Enum::V`・`crate::x`・`super::x`・`self::x`。先頭は `crate`・`self`・`super`・子モジュール・`use` した名前のどれか |
| `use` | `use foo::bar;`・`use foo::{a, b as c};`・`use foo::*;`（公開された項目すべて）・`use crate::util;`（モジュールを名指す）。効果はそのファイルだけ（Go の import と同じ）。`pub use`（再公開）と variant の `use` はない |
| 名前の衝突 | 同じモジュールの項目と同名の `use`、同名の `use` 2 つはエラー。glob（`*`）同士で衝突した名前は使うとエラー（曖昧）。モジュールの項目は glob に勝つ |
| trait のメソッド | trait が `use` されていなくても見つかる（従来どおり。単純さを優先） |
| core・prelude | どのモジュールからも従来どおり見える |
| エントリ | `#[main]`・`#[handler]` はルートモジュールに置く。`#[test]` はどのモジュールにも置ける |

## 実装

名前の書き換え（name mangling）で実現する。構文解析の直後、`compiler/modres.kek`（接頭辞 `mr_`）がファイルごとのスコープで名前を解決し、サブモジュールの項目を `foo$bar` のように `$` で区切ったグローバルな名前に置き換える。以降のパス（型検査・lowering・定義ハッシュ・assure など）は従来どおり一意なグローバル名だけを見る。

- ルートモジュールの項目は名前を変えない。サブディレクトリも `use` もないプログラムでは解決のパスは走らず（`crate::`・`self::` のパスがあるときだけ走る）、定義ハッシュ・`kekkai.assure.lock` は変わらない。
- `$` は利用者のソースには書けない（字句解析は受け付けるが、生成コード以外ではエラー）。`#[derive]`・`kek test` のハーネス・プロパティテストの生成器は書き換え後の名前をそのまま使う。
- 表示ではすべて `foo::bar` に戻す：診断、`kek caps`、`kek test` のテスト名（`-run` もこの名前に照合する）、`kek hash`、`kek assure` のキー。
- 構文木は書き換えずに新しいノードを作る（`kek fmt` とデーモンの構文解析のキャッシュは元の形を見る）。
- メソッドとフィールドの可視性は型が要るので、型検査の後に検査する（`mr_check_privacy`）。非公開のメソッドと struct のフィールドには、解決のパスが内部の属性（`#[__private]`・`#[__private_fields(...)]`）と定義したモジュール（`#[__mod(...)]`）を付ける。
- 診断の例：`function `bar` is private to module `foo``、`cannot find `x` in module `foo``、`unresolved module `nope``、``x` is ambiguous (imported by `use a::*` and `use b::*`)`。
